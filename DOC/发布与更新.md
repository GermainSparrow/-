# 发布、服务器推送与自动更新说明

## 当前结论

公司测试服务器已经提供软件发布中心，当前可以把 Windows 安装包推送到服务器，并向普通用户提供最新版本下载。

| 用途 | 地址或限制 |
| --- | --- |
| 管理员发布入口 | `https://wxbackend.sclh.com.cn/software-management` |
| 普通用户下载入口 | `https://wxbackend.sclh.com.cn/downloads` |
| 发布 API 基址 | `https://wxbackend.sclh.com.cn` |
| 单个安装包上限 | 500 MB |
| 本项目上传文件 | `release/document-sanitizer-restore-版本号-win-x64.exe` |
| 权限 | 只有后台 `super_admin` 可以发布；普通用户只能下载 |
| 当前环境 | 测试环境，不应当作正式生产发布域名对外承诺 |

需要特别区分以下两项能力：

1. **软件中心发布**已经可用：保存每个软件的历史安装包，普通用户始终下载最新版本，支持 HTTPS、SHA-256 展示和 HTTP Range 断点下载。
2. **Electron 应用内自动更新**尚未接入：`electron-updater` 还需要同一路径下的 `latest.yml`、`.exe` 和 `.exe.blockmap` 三个静态文件。当前软件中心只接收单个安装包，不能把软件中心下载地址直接填写到 `build.publish[0].url`。

因此，目前发布后用户可以从软件下载页手工下载安装新版本；已经安装的客户端暂时不会通过 `electron-updater` 自动升级。

## 当前发布方式

本项目使用 `electron-builder` 生成 Windows NSIS 安装包，使用 `electron-updater` 检查和安装更新。

当前实际可用的发布方式是将 `release/document-sanitizer-restore-版本号-win-x64.exe` 上传到公司软件中心。首次安装和后续升级都由用户从下载页获取最新安装包并运行。

### 方式一：通过网页发布（推荐）

1. 打开 `https://wxbackend.sclh.com.cn/software-management`。
2. 使用后台超级管理员账号登录。内控审计人员账号没有软件发布权限。
3. 首次发布时点击“新增软件”，建议填写：
   - 软件名称：`文档脱敏还原软件`
   - 适用平台：`Windows 10/11 x64`
   - 软件说明：按当前版本功能填写
   - 公开状态：上架
4. 点击该软件的“上传新版”，填写与 `package.json` 完全一致的版本号，例如 `0.2.1`。
5. 选择 `release/document-sanitizer-restore-0.2.1-win-x64.exe`，填写更新说明，然后点击“上传并发布”。
6. 打开 `https://wxbackend.sclh.com.cn/downloads`，确认软件名称、版本号、文件大小和下载按钮正确。
7. 实际下载一次安装包，并核对文件大小或页面显示的 SHA-256。

同一软件下不能重复上传相同版本号。如需修复已经发布的版本，必须递增 `package.json` 版本号后重新构建，不能覆盖原版本。

### 方式二：使用 PowerShell 推送

下面命令应在本项目根目录执行。它会安全提示输入后台账号密码，不会把密码保存到文档、脚本或命令历史中；随后读取 `package.json` 的版本，查找或创建软件条目，并上传对应安装包。

```powershell
$ErrorActionPreference = 'Stop'

$baseUrl = 'https://wxbackend.sclh.com.cn'
$productName = '文档脱敏还原软件'
$package = Get-Content -LiteralPath '.\package.json' -Raw -Encoding UTF8 | ConvertFrom-Json
$version = [string]$package.version
$installer = Get-Item -LiteralPath ".\release\document-sanitizer-restore-$version-win-x64.exe"

$credential = Get-Credential -Message '输入软件中心超级管理员账号和密码'
$loginBodyJson = @{
  username = $credential.UserName
  password = $credential.GetNetworkCredential().Password
} | ConvertTo-Json
$loginBody = [System.Text.Encoding]::UTF8.GetBytes($loginBodyJson)

$session = Invoke-RestMethod `
  -Method Post `
  -Uri "$baseUrl/admin/auth/login" `
  -ContentType 'application/json; charset=utf-8' `
  -Body $loginBody

$headers = @{ Authorization = "Bearer $($session.token)" }
$products = @(
  Invoke-RestMethod `
    -Method Get `
    -Uri "$baseUrl/software-center/admin/products" `
    -Headers $headers
)
$product = @($products | Where-Object { $_.name -eq $productName })[0]

if (-not $product) {
  $productBodyJson = @{
    name = $productName
    platform = 'Windows 10/11 x64'
    description = '本地文档脱敏与实体级还原工具'
    isActive = $true
    sortOrder = 0
  } | ConvertTo-Json
  $productBody = [System.Text.Encoding]::UTF8.GetBytes($productBodyJson)

  $product = Invoke-RestMethod `
    -Method Post `
    -Uri "$baseUrl/software-center/admin/products" `
    -Headers $headers `
    -ContentType 'application/json; charset=utf-8' `
    -Body $productBody
}

if (-not $product.isActive) {
  $activationBody = [System.Text.Encoding]::UTF8.GetBytes((@{ isActive = $true } | ConvertTo-Json))
  $product = Invoke-RestMethod `
    -Method Patch `
    -Uri "$baseUrl/software-center/admin/products/$($product.id)" `
    -Headers $headers `
    -ContentType 'application/json; charset=utf-8' `
    -Body $activationBody
}

$releaseNotes = Read-Host '输入本次更新说明'
$uploadUrl = "$baseUrl/software-center/admin/products/$($product.id)/releases"

curl.exe --fail-with-body --request POST `
  --header "Authorization: Bearer $($session.token)" `
  --form-string "version=$version" `
  --form-string "releaseNotes=$releaseNotes" `
  --form-string "originalName=$($installer.Name)" `
  --form "file=@$($installer.FullName);type=application/octet-stream" `
  $uploadUrl

if ($LASTEXITCODE -ne 0) {
  throw "安装包上传失败，curl 退出码：$LASTEXITCODE"
}

$publicProducts = @(
  Invoke-RestMethod -Method Get -Uri "$baseUrl/software-center/products"
)
$published = @($publicProducts | Where-Object { $_.name -eq $productName })[0]
if (-not $published -or $published.latestRelease.version -ne $version) {
  throw '服务器未返回刚发布的版本，请登录管理页检查发布状态。'
}

Write-Host "发布成功：$productName v$version" -ForegroundColor Green
Write-Host '用户下载页：https://wxbackend.sclh.com.cn/downloads'
```

如果接口提示“版本已存在”，应提高 `package.json` 的 `version` 并重新执行 `npm.cmd run dist:win`，不要删除或覆盖已经交付给用户的同版本安装包。

## Electron 自动更新当前状态

`package.json` 中的更新地址当前是占位值：

```json
"url": "https://example.com/updates/document-sanitizer-restore/win/"
```

该占位地址尚未对应任何可用服务。不要替换为以下地址：

- `https://wxbackend.sclh.com.cn/downloads`
- `https://wxbackend.sclh.com.cn/software-center/products/<软件ID>/download`

这些地址用于网页下载或直接下载最新安装包，不提供 `electron-updater` 所需的 `latest.yml` 和 `.blockmap`。

将来服务器增加独立静态更新目录后，再替换成稳定的 HTTPS 地址，例如：

```json
"url": "https://download.your-company.com/updates/document-sanitizer-restore/win/"
```

该静态更新地址发布后不要随意变更。客户端会从该地址读取 `latest.yml`。在该目录真正部署并完成下文验收前，不得宣称应用内自动更新已经可用。

## 自动更新服务器完整要求（未来接入）

### 工作方式

更新服务器只负责提供静态文件下载，不需要数据库、消息队列、WebSocket 或专门的通知后台。当前客户端在软件启动后主动检查更新，流程如下：

```text
客户端启动
  -> 请求 latest.yml
  -> 比较版本号
  -> 下载 .blockmap 和/或 .exe
  -> 校验安装包
  -> 提示用户重启安装
```

因此，IIS、Nginx、Apache、对象存储或带 HTTPS 的静态文件服务都可以使用。服务器不需要安装 Node.js、Electron 或本项目源码。

### 强制要求

| 项目 | 要求 |
| --- | --- |
| 更新地址 | 提供固定的基础 URL，例如 `https://download.your-company.com/updates/document-sanitizer-restore/win/` |
| 网络范围 | 所有需要更新的客户端都必须能访问；外网用户不能使用仅内网可达的地址 |
| HTTPS | 正式环境使用 HTTPS，证书必须有效、未过期，并由客户端信任的证书机构签发 |
| 访问方式 | 当前客户端没有登录和鉴权逻辑，下载目录必须允许匿名只读访问，不能出现登录页、验证码或 WAF 人机验证 |
| HTTP 方法 | 至少支持 `GET` 和 `HEAD` |
| 范围请求 | 安装包应支持 HTTP Range 请求，返回 `206 Partial Content` 和 `Content-Range`，用于差分下载和断点传输 |
| 文件完整性 | 服务器和 CDN 不能修改、重新压缩、转码或重命名安装包及 `.blockmap` 文件 |
| 状态码 | 文件存在返回 `200`；范围请求返回 `206`；文件不存在返回 `404`，不能用 `200` 返回错误页面 |
| 重定向 | 最好直接从最终 HTTPS 地址提供文件；如必须重定向，应保持稳定且不能跳转到登录页 |
| 上传权限 | 普通客户端只有读取权限；上传、替换和删除权限只授予发布账号或 CI/CD 账号 |

### 文件与目录结构

三个文件必须位于同一更新目录，并且来自同一次构建：

```text
/updates/document-sanitizer-restore/win/
├── latest.yml
├── document-sanitizer-restore-0.2.1-win-x64.exe
└── document-sanitizer-restore-0.2.1-win-x64.exe.blockmap
```

对应的访问地址示例：

```text
https://download.your-company.com/updates/document-sanitizer-restore/win/latest.yml
https://download.your-company.com/updates/document-sanitizer-restore/win/document-sanitizer-restore-0.2.1-win-x64.exe
https://download.your-company.com/updates/document-sanitizer-restore/win/document-sanitizer-restore-0.2.1-win-x64.exe.blockmap
```

不要手工修改 `latest.yml` 中的文件名、文件大小和 SHA-512 校验值，也不要把不同构建生成的文件混放在一起。

### 缓存要求

`latest.yml` 决定客户端能看到哪个版本，不能长期缓存。建议响应头：

```http
Cache-Control: no-store, no-cache, must-revalidate, max-age=0
```

带版本号的 `.exe` 和 `.blockmap` 发布后不应再被覆盖，可以长期缓存：

```http
Cache-Control: public, max-age=31536000, immutable
```

如果前面使用 CDN，必须对 `latest.yml` 单独关闭缓存或在每次发布后立即刷新该文件的 CDN 缓存。不要只刷新安装包而遗漏 `latest.yml`。

### 容量与带宽

当前 `0.2.1` 安装包约为 126 MB。服务器主要消耗磁盘和下行流量，对 CPU、内存没有明显要求。

流量可按以下公式预估：

```text
一次完整更新流量 ≈ 安装包大小 × 更新客户端数量
```

以当前安装包计算：

| 更新客户端数量 | 一次全量更新约需下行流量 |
| ---: | ---: |
| 100 台 | 12.3 GB |
| 1,000 台 | 122.6 GB |
| 10,000 台 | 1.2 TB |

差分更新可能降低实际流量，但容量规划不应完全依赖差分更新。建议至少保留当前版本和前两个版本；小规模内部使用可按 `1 vCPU、1 GB 内存、10 GB 可用磁盘、10-20 Mbps` 作为静态文件服务器的实用起点。用户较多或集中更新时，优先使用对象存储加 CDN，或提高出口带宽。

### 发布顺序

每次发布必须按下面顺序操作，避免客户端先读到新版本信息，却下载不到新安装包：

1. 提升 `package.json` 中的 `version` 并完成构建。
2. 上传新版本 `.exe`。
3. 上传同版本 `.exe.blockmap`。
4. 确认上述两个文件已可下载。
5. 最后上传或替换 `latest.yml`。
6. 清除 `latest.yml` 的 CDN/代理缓存。
7. 从客户端所在网络执行验收检查。

建议先上传到临时文件名，完成后再由服务器原子重命名为正式文件名。旧版本文件至少保留到新版本验证完成，不要在发布新版本前删除当前线上版本。

如果新版本有问题，不要把 `latest.yml` 改回更低版本，也不要用相同版本号覆盖安装包。应修复问题、使用更高版本号重新构建并发布。

### 安全要求

- 更新目录只存放公开发布文件，不放源码、配置文件、证书私钥、用户文档或脱敏数据。
- 上传账号与匿名下载权限分离；上传账号使用强密码或 SSH 密钥，并限制可写目录。
- 关闭目录浏览，外部用户只能通过明确的文件 URL 下载。
- 保留访问日志和发布操作日志，至少记录时间、客户端 IP、请求路径、状态码和发送字节数。
- 建议监控 `latest.yml` 的可用性、证书到期时间、服务器磁盘空间和异常 `4xx/5xx` 比例。
- 服务器 HTTPS 只能保护传输过程；Windows 安装包仍建议配置代码签名证书，以避免“未知发布者”提示并降低安装包被替换的风险。

### Nginx 配置示例

下面示例假设文件实际存放于 `/srv/downloads/updates/document-sanitizer-restore/win/`。证书配置需要合并到服务器现有 HTTPS 配置中。

```nginx
server {
    listen 443 ssl;
    server_name download.your-company.com;
    root /srv/downloads;

    location = /updates/document-sanitizer-restore/win/latest.yml {
        try_files $uri =404;
        default_type text/yaml;
        add_header Cache-Control "no-store, no-cache, must-revalidate, max-age=0" always;
    }

    location ~ ^/updates/document-sanitizer-restore/win/.+\.(exe|blockmap)$ {
        try_files $uri =404;
        default_type application/octet-stream;
        add_header Cache-Control "public, max-age=31536000, immutable" always;
    }

    location /updates/document-sanitizer-restore/win/ {
        autoindex off;
        try_files $uri =404;
    }
}
```

Nginx 静态文件服务默认支持字节范围请求。若前面还有反向代理、网关或 CDN，需要再次确认这些中间层没有去掉 `Range`、`Content-Range` 和 `Accept-Ranges`。

### IIS 配置检查项

使用 Windows IIS 时，运维需要确认：

- 已安装并启用“静态内容”功能。
- `.yml` MIME 类型设置为 `text/yaml` 或 `application/octet-stream`。
- `.blockmap` 和 `.exe` MIME 类型设置为 `application/octet-stream`。
- 请求筛选没有禁止 `.yml`、`.blockmap` 或 `.exe` 扩展名。
- `latest.yml` 禁止缓存，带版本号的安装包和 `.blockmap` 可长期缓存。
- IIS、反向代理和防火墙允许约 126 MB 或更大的文件下载。
- 匿名身份验证对更新目录开启，写入权限对匿名用户关闭。

### 上线验收

将示例域名和版本替换为正式值后执行：

```powershell
$baseUrl = "https://download.your-company.com/updates/document-sanitizer-restore/win"
$installer = "document-sanitizer-restore-0.2.1-win-x64.exe"

curl.exe -I "$baseUrl/latest.yml"
curl.exe -I "$baseUrl/$installer"
curl.exe -sS -D - -o NUL -H "Range: bytes=0-1023" "$baseUrl/$installer"
```

验收结果应满足：

- `latest.yml` 和安装包返回 `200 OK`。
- `latest.yml` 的 `Cache-Control` 不允许长期缓存。
- 范围请求返回 `206 Partial Content`，并包含 `Content-Range: bytes 0-1023/文件总大小`。
- 浏览器可直接下载 `latest.yml`、`.exe` 和 `.blockmap`，不会跳转到登录或拦截页面。
- 在一台已安装旧版本的真实 Windows 电脑上启动软件，能够发现、下载并提示安装新版本。

### 启用自动更新前仍需确认的信息

软件中心的网页发布地址已经确定，但 Electron 自动更新的静态目录尚未部署。正式启用自动更新前，仍需要服务器管理员确认并提供：

1. 最终 HTTPS 基础地址，例如 `https://download.company.com/updates/document-sanitizer-restore/win/`。
2. 服务器类型，例如 IIS、Nginx、对象存储或其他静态文件服务。
3. 文件上传方式和发布账号，例如 SFTP、服务器共享目录、对象存储控制台或 CI/CD。
4. 服务对象是公司内网用户、VPN 用户还是互联网用户，以及预计客户端数量。
5. HTTPS 证书负责人、证书续期方式和 CDN 使用情况。

收到最终自动更新基础地址后，需要先验证 `latest.yml`、`.exe` 和 `.blockmap` 均可匿名访问，再修改 `package.json` 中的 `build.publish[0].url`，最后重新构建安装包。更新地址会写入安装后的应用，不能等安装包已经分发后再补填。

## 每次发版流程

1. 修改 `package.json` 的 `version`，例如从 `0.2.0` 改成 `0.2.1`。
2. 同步修改 `package-lock.json` 中的根项目版本。推荐在项目根目录执行：

```powershell
npm.cmd version 0.2.1 --no-git-tag-version
```

3. 执行完整构建：

```powershell
npm.cmd run dist:win
```

4. 确认本次构建产生以下三个同版本文件：

```text
latest.yml
document-sanitizer-restore-版本号-win-x64.exe
document-sanitizer-restore-版本号-win-x64.exe.blockmap
```

5. 使用本文“方式一”或“方式二”把 `.exe` 安装包推送到公司软件中心。
6. 打开 `https://wxbackend.sclh.com.cn/downloads`，确认公开页已经显示新版本并实际下载验收。
7. 更新 `DOC/版本记录.md`，记录版本号、发布日期、主要变更和已知限制。
8. 在 Electron 自动更新静态目录尚未上线时，将 `latest.yml` 和 `.blockmap` 作为本次构建留档，不要上传到软件中心，也不要宣称客户端可以自动升级。

将来自动更新静态目录上线后，才按前文“发布顺序”把 `.exe`、`.blockmap`、`latest.yml` 依次上传到固定更新目录。届时已安装用户启动软件后才会发现、下载并提示安装新版本。

## 注意事项

- `version` 必须递增，否则客户端不会认为有新版本。
- `latest.yml`、安装包 `.exe`、`.blockmap` 必须来自同一次构建，不能混用。
- 当前公司软件中心只上传 `.exe`；它不是 Electron Generic 自动更新目录。
- 旧的解压版用户无法自动更新，必须先安装一次新的 NSIS 安装包。
- 在独立静态更新目录上线前，所有用户升级都需要从 `https://wxbackend.sclh.com.cn/downloads` 手工下载并运行最新版安装包。
- 对外正式发布建议配置 Windows 代码签名证书，否则系统可能显示“未知发布者”。
- 当前未配置签名证书，构建日志中出现签名步骤不代表已完成可信代码签名。
