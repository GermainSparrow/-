# 开发文档

## 项目定位

文档脱敏还原软件是一个基于 Electron 的桌面端应用。当前版本提供基础工作台，用于后续接入文档脱敏、映射表还原、任务记录、规则配置和导出能力。

当前工程重点是搭建桌面应用外壳和本地文件选择入口，业务处理能力尚未实现。

## 技术栈

- Electron：桌面应用运行时。
- Node.js：主进程能力和本地文件路径处理。
- HTML、CSS、JavaScript：渲染层页面和交互。

## 运行方式

推荐使用 `npm.cmd`，避免部分 PowerShell 环境中 `npm.ps1` 的执行策略或包装脚本问题。

```powershell
npm.cmd install
npm.cmd start
```

依赖已经安装后，也可以直接运行 Electron：

```powershell
.\node_modules\electron\dist\electron.exe .
```

## 模块说明

### 主进程

文件：`src/main/main.js`

职责：

- 创建主窗口，窗口标题为“文档脱敏还原软件”。
- 设置窗口尺寸、最小尺寸、背景色和渲染安全选项。
- 加载渲染层页面 `src/renderer/index.html`。
- 注册 `app:get-version` IPC 处理器，返回 `package.json` 中的应用版本。
- 注册 `dialog:open-documents` IPC 处理器，打开系统文件选择窗口并返回文件列表。

安全配置：

- `contextIsolation: true`
- `nodeIntegration: false`
- `sandbox: true`

这表示渲染层不能直接使用 Node.js 能力，必须通过 preload 暴露的受控 API 调用主进程能力。

### 预加载脚本

文件：`src/main/preload.js`

职责：

- 通过 `contextBridge.exposeInMainWorld` 暴露 `window.desktopApi`。
- 暴露 `getVersion()` 获取应用版本。
- 暴露 `openDocuments()` 调用系统文件选择窗口。

新增主进程能力时，应优先在 preload 中暴露最小必要接口，不要把 `ipcRenderer` 或 Node.js 原生能力整体暴露给渲染层。

### 渲染层页面

文件：`src/renderer/index.html`

职责：

- 定义应用基础布局，包括侧边导航、顶部标题、处理模式工具栏、待处理文档面板。
- 提供“选择文档”按钮和文件列表容器。

当前导航包括：

- 工作台
- 任务记录
- 规则配置
- 系统设置

除“工作台”外，其余导航当前仅为界面占位。

### 渲染层交互

文件：`src/renderer/renderer.js`

职责：

- 初始化应用版本号显示。
- 绑定“选择文档”按钮点击事件。
- 调用 `window.desktopApi.openDocuments()` 获取用户选择的文件。
- 将文件列表渲染到页面中。
- 绑定脱敏处理、还原处理两个模式按钮的选中态切换。

### 样式

文件：`src/renderer/styles.css`

职责：

- 定义应用布局、侧边栏、顶部栏、模式按钮、文档面板、空状态和文件列表样式。
- 当前采用浅色工作台风格，主色为绿色系，强调色为棕橙色。

## 当前功能流程

1. 启动应用。
2. 主进程创建桌面窗口并加载渲染页面。
3. 渲染层通过 preload 获取当前版本号。
4. 用户点击“选择文档”。
5. 主进程打开系统文件选择窗口。
6. 用户选择一个或多个文档。
7. 主进程返回文件路径、文件名和扩展名。
8. 渲染层展示待处理文件列表。

## 支持的入口文件类型

当前文件选择窗口允许选择以下扩展名：

- `doc`
- `docx`
- `pdf`
- `txt`
- `md`
- `xlsx`

注意：当前仅支持选择这些文件，还没有实现对应格式的内容解析和处理。

## 设计清单 V1

### 1. 产品边界

- 支持两种处理模式：
  - 不可逆脱敏：导出文件不含原始敏感信息，不能还原。
  - 可逆实体脱敏：导出脱敏文件和加密映射文件，输入口令或密钥文件后可实体级还原。
- 明确用户文案：可逆模式不是合规匿名化，只是本地加密的实体替换。
- AI 只接收脱敏后的内容，禁止原文进入 AI 请求、日志、缓存。

### 2. 还原规则

- 默认只做实体级还原：看到 `甲公司` 才还原为 `路航公司`，看到 `李四` 才还原为 `李明`。
- 如果 AI 摘要把 `李四` 删除，系统不能凭空补回 `李明`。
- 若业务必须实现“摘要后还能还原被改写内容”，建议给 AI 的文本携带稳定标签。

示例：

```text
脱敏给 AI：甲公司<ORG_001>董事长李四<PERSON_001>涨薪10%
AI 摘要：甲公司<ORG_001>董事长李四<PERSON_001>在深思熟虑后涨薪10%
还原：路航公司董事长李明在深思熟虑后涨薪10%
```

- 如果 AI 删除标签，则仍不能还原该实体。

### 3. 加密与密钥

- 禁止内置固定主密钥。
- 每个文档生成随机 `DEK` 文件密钥。
- 用 `DEK` 加密实体映射表。
- `DEK` 再由用户口令派生密钥或密钥文件加密。
- 映射文件和脱敏文件分开保存，避免单文件泄露即可还原。
- 加密包建议包含：
  - `version`
  - `docId`
  - `createdAt`
  - `kdf`：`scrypt` 或 `Argon2id` 参数、salt
  - `wrappedDek`
  - `encryptedMapping`
  - `algorithm`：`AES-256-GCM` 或 `ChaCha20-Poly1305`

### 4. 实体映射设计

- 映射项至少包含：
  - 实体类型：公司、人名、手机号、身份证、地址、邮箱、账号
  - 原文值
  - 脱敏值
  - 稳定 ID：`ORG_001`、`PERSON_001`
  - 出现位置或上下文 hash
- 同一实体在同一文档内应稳定替换。
- 不同文档默认使用不同映射，避免跨文档关联。
- 替换时优先处理长字符串，避免 `李明`、`明` 这类重叠误替换。

### 5. PDF / Word 处理

- PDF：
  - 不能只画黑块遮盖。
  - 文本型 PDF 要删除底层文本或重新生成 PDF。
  - 扫描 PDF 需要 OCR 后识别敏感信息；OCR 失败时提示风险。
- Word：
  - 处理正文、表格、页眉页脚、脚注尾注、批注、修订记录、隐藏文本、文档属性、嵌入对象。
  - 导出前清理元数据。
- 对无法可靠处理的对象要阻断或提示“存在未确认内容”，不能静默通过。

### 6. Electron 安全清单

- 敏感逻辑放在 main process、worker 或独立子进程。
- renderer 不直接接触密钥、映射明文、原始文件全文。
- 开启 `contextIsolation`、`sandbox`，关闭 renderer 的 Node 权限。
- IPC 只暴露最小 API：导入、脱敏、预览、导出、解锁映射、还原。
- IPC 参数必须做 schema 校验。
- 禁止加载不可信远程页面。
- 日志、崩溃报告、临时文件不得写入原文敏感信息。

### 7. 用户流程

1. 导入文件。
2. 选择模式：不可逆脱敏 / 可逆实体脱敏。
3. 预览识别出的实体，允许用户确认、删除、补充。
4. 执行脱敏。
5. 可逆模式输出脱敏文件、加密映射文件、脱敏报告。
6. 还原时输入脱敏文本或文件、加密映射文件、口令或密钥文件。

### 8. 测试验收

- 验证导出的 PDF / Word 不能复制出原始敏感信息。
- 验证 Word 批注、修订、元数据无泄露。
- 验证错误口令无法解密映射。
- 验证 AI 删除实体后不会错误补回。
- 验证带稳定标签的 AI 摘要可以实体级还原。
- 验证安装包、asar、bundle 中不存在固定密钥。

## 后续开发建议

后续实现应以“设计清单 V1”为约束，先补齐安全边界、实体映射、加密映射文件和文档处理能力，再扩展任务记录、规则配置和批处理。

### 实现方向

- 新增独立文档处理层，负责文件读取、格式识别、文本抽取、敏感实体识别、文档写回和元数据清理。
- 新增实体映射层，负责同文档稳定替换、稳定 ID 生成、上下文定位和可逆映射维护。
- 新增加密层，负责随机 `DEK` 生成、映射表加密、口令或密钥文件派生密钥、加密包读写。
- 新增任务层，负责任务状态流转、错误收集、脱敏报告生成和输出目录管理。
- 新增还原层，按实体映射和稳定标签执行实体级还原，不补回已被 AI 删除的实体。

### IPC 设计

后续 IPC 仅暴露最小必要能力：

- `document:import`：导入文件。
- `sanitize:preview`：预览识别出的实体。
- `sanitize:run`：执行脱敏。
- `output:export`：导出脱敏文件、加密映射文件和脱敏报告。
- `mapping:unlock`：使用口令或密钥文件解锁映射。
- `restore:run`：执行实体级还原。
- `task:get-list`：获取任务记录。

IPC 返回值建议统一结构：

```js
{
  ok: true,
  data: {},
  error: null
}
```

失败时：

```js
{
  ok: false,
  data: null,
  error: {
    code: "ERROR_CODE",
    message: "错误说明"
  }
}
```

### 状态管理

任务状态建议从简单枚举开始：

- `pending`：待处理
- `running`：处理中
- `success`：处理成功
- `failed`：处理失败

渲染层展示文案可映射为“待处理”、“处理中”、“已完成”、“失败”。

### 安全和隐私

本项目处理的文档可能包含敏感信息，后续开发应遵守以下约束：

- 默认只在本地处理文件，不上传原始文档。
- 映射表和处理日志应避免明文暴露敏感内容。
- 导出文件应写入用户明确选择的目录。
- 错误日志中不要记录完整敏感字段。
- 渲染层不直接访问文件系统，文件能力通过主进程受控暴露。

## 开发约定

- 保持主进程、preload、渲染层职责分离。
- 新增本地能力时先设计 IPC 接口，再实现调用链。
- UI 文案保持中文一致性。
- 文件编码统一使用 UTF-8。
- 文档更新与版本记录同步维护。
