# 开发文档

## 项目定位

文档脱敏还原软件是一个基于 Electron 的桌面端应用。当前版本已提供本地不可恢复脱敏、可恢复实体脱敏、加密映射文件导出和实体级还原能力。

当前工程优先保证原文不上云、敏感处理在主进程执行、可恢复映射加密保存。已支持本地自定义实体集；任务记录、批处理队列和安装包打包仍待后续完善。

## 技术栈

- Electron：桌面应用运行时。
- Node.js：主进程能力和本地文件路径处理。
- HTML、CSS、JavaScript：渲染层页面和交互。
- JSZip：Word DOCX 解析和写回。
- ExcelJS、PDF.js、pdf-lib、fontkit：历史处理模块依赖，当前产品入口暂未开放 XLSX/PDF 文件。
- Zod：IPC 参数校验。
- Node.js `crypto`：映射文件加密和口令派生。

## 运行方式

推荐使用 `npm.cmd`，避免部分 PowerShell 环境中 `npm.ps1` 的执行策略或包装脚本问题。

```powershell
npm.cmd install
npm.cmd start
```

## 模块说明

### 主进程

文件：`src/main/main.js`

职责：

- 创建主窗口，窗口标题为“文档脱敏还原软件”。
- 设置窗口尺寸、最小尺寸、背景色和渲染安全选项。
- 加载渲染层页面 `src/renderer/index.html`。
- 注册 `app:get-version` IPC 处理器，返回 `package.json` 中的应用版本。
- 注册文档导入、脱敏预览、脱敏执行、输出目录选择、映射解锁、还原执行和实体集管理等 IPC 处理器。

安全配置：

- `contextIsolation: true`
- `nodeIntegration: false`
- `sandbox: true`

这表示渲染层不能直接使用 Node.js 能力，必须通过 preload 暴露的受控 API 调用主进程能力。

### 预加载脚本

文件：`src/main/preload.js`

职责：

- 通过 `contextBridge.exposeInMainWorld` 暴露 `window.desktopApi`。
- 暴露 `getVersion()` 获取应用版本。
- 暴露 `importDocuments()`、`importDroppedDocuments()`、`previewSanitize()`、`runSanitize()`、`selectOutputDirectory()`、`unlockMapping()`、`runRestore()`、`listEntitySets()`、`saveEntitySet()`、`deleteEntitySet()`、`importEntitySet()`、`exportEntitySet()` 等最小 API。
- `importDroppedDocuments()` 只接收渲染层拖拽得到的 `File` 对象，由 preload 使用 Electron `webUtils.getPathForFile()` 转换为本地路径后交给主进程校验和授权。

新增主进程能力时，应优先在 preload 中暴露最小必要接口，不要把 `ipcRenderer` 或 Node.js 原生能力整体暴露给渲染层。

### 渲染层页面

文件：`src/renderer/index.html`

职责：

- 定义应用基础布局，包括侧边导航、顶部标题、脱敏工作流、还原工作流和实体集管理页。
- 提供 DOCX 上传窗口、拖拽上传、粘贴文本输入、输出目录选择、实体确认、实体集维护、可恢复凭据、映射文件选择和执行按钮。

当前导航包括：

- 工作台
- 文档脱敏
- 内容还原
- 实体集

### 渲染层交互

文件：`src/renderer/renderer.js`

职责：

- 初始化应用版本号显示。
- 管理脱敏、还原和实体集三个工作流的前端状态。
- 调用 preload 暴露的最小 API 与主进程通信。
- 渲染输入内容、阻断结果、实体表格、文本结果、输出状态和错误提示。

### 样式

文件：`src/renderer/styles.css`

职责：

- 定义应用布局、侧边栏、顶部栏、模式按钮、文档面板、表单、实体表格、状态提示和文件列表样式。
- 当前采用浅色工作台风格，主色为绿色系，强调色为棕橙色。

### 主进程服务层

目录：`src/main/services/`

职责：

- 实体字段识别、词库字段匹配、长字符串优先替换和实体级还原。
- 加密映射文件生成和解密。
- DOCX 的正文、元数据、自定义 XML 文本抽取、图片风险提示、脱敏写回和还原写回。
- 粘贴文本的内存识别、脱敏、还原和 TXT 导出。
- 脱敏和还原结果导出，不额外生成报告文件。
- 本地实体集读取、保存、删除、JSON/CSV 导入导出。
- IPC 参数 schema 校验和统一响应结构。

## 当前功能流程

1. 启动应用。
2. 主进程创建桌面窗口并加载渲染页面。
3. 渲染层通过 preload 获取当前版本号。
4. 用户点击上传或拖拽 DOCX 文件，或粘贴待脱敏文本。
5. 用户选择不可恢复脱敏或可恢复实体脱敏。
6. 主进程抽取文本并识别规则字段和已启用实体集中的词库字段。
7. 用户确认、删除或补充实体。
8. 用户选择输出目录并执行脱敏；若 DOCX 包含图片，需确认图片内内容不会被修改后才能导出。
9. 不可恢复模式导出脱敏文件或 TXT；可恢复模式额外导出加密映射文件。
10. 还原时用户选择 DOCX 文件或粘贴文本，并选择加密映射文件、口令或密钥文件，主进程执行实体级还原。
11. DOCX 脱敏文件命名为 `原文件名_已脱敏.docx`，DOCX 还原文件命名为 `原文件名_已还原.docx`。

## 支持的输入类型

当前产品入口支持：

- Word 文件：仅 `docx`，支持点击上传或拖拽单个 DOCX 到上传窗口
- 粘贴文本：页面文本框输入

其他文件类型暂不开放入口。旧版 `doc` 需另存为 `docx` 后处理；`pdf`、`xlsx`、`txt`、`md` 等文件暂不作为文件输入，纯文本内容请复制到粘贴文本框。

## 设计清单 V1

### 1. 产品边界

- 支持两种处理模式：
  - 不可逆脱敏：导出文件不含原始敏感信息，不能还原。
  - 可逆实体脱敏：导出脱敏文件和加密映射文件，输入口令或密钥文件后可实体级还原。
- 明确用户文案：可逆模式不是合规匿名化，只是本地加密的实体替换。
- AI 只接收脱敏后的内容，禁止原文进入 AI 请求、日志、缓存。

### 2. 还原规则

- 默认只做实体级还原：看到 `甲公司` 才还原为 `路航公司`，看到 `李四` 才还原为 `李明`。
- 如果 AI 摘要把 `李四` 删除，系统不能凭空补回 `李明`。
- 若业务必须实现“摘要后还能还原被改写内容”，建议给 AI 的文本携带稳定标签。

示例：

```text
脱敏给 AI：甲公司<ENTITY_001>董事长李四<ENTITY_002>涨薪10%
AI 摘要：甲公司<ENTITY_001>董事长李四<ENTITY_002>在深思熟虑后涨薪10%
还原：路航公司董事长李明在深思熟虑后涨薪10%
```

- 如果 AI 删除标签，则仍不能还原该实体。

### 3. 加密与密钥

- 禁止内置固定主密钥。
- 每个文档生成随机 `DEK` 文件密钥。
- 用 `DEK` 加密实体映射表。
- `DEK` 再由用户口令派生密钥或密钥文件加密。
- 映射文件和脱敏文件分开保存，避免单文件泄露即可还原。
- 加密包建议包含：
  - `version`
  - `docId`
  - `createdAt`
  - `kdf`：`scrypt` 或 `Argon2id` 参数、salt
  - `wrappedDek`
  - `encryptedMapping`
  - `algorithm`：`AES-256-GCM` 或 `ChaCha20-Poly1305`

### 4. 实体映射设计

- 映射项至少包含：
  - 原文值
  - 脱敏值
  - 稳定 ID：`ENTITY_001`
  - 出现位置或上下文 hash
- 同一实体在同一文档内应稳定替换。
- 不同文档默认使用不同映射，避免跨文档关联。
- 替换时优先处理长字符串，避免 `李明`、`明` 这类重叠误替换。
- 自定义实体集用于维护常见公司、机构等业务字段；预览时按精确包含、最长优先、去重策略生成来源为“词库”的实体。
- 用户侧不再维护实体类型，新生成实体统一保留 `ENTITY_001`、`ENTITY_002` 这类稳定 ID；词库/机构名默认生成 `A公司`、`B集团` 这类相近脱敏值，结构化字段仍默认使用稳定占位标签；底层 `type` 字段仅为兼容旧映射和旧数据保留。
- 内置蜀道系公司实体集只覆盖官方公开且可追溯的直属、核心下属和成员单位，不承诺覆盖蜀道集团全部各级企业。

### 5. Word / 文本处理

- Word：
  - 当前产品入口仅支持 DOCX。
  - 处理正文、表格、页眉页脚、脚注尾注、批注、文档属性、外部关系目标和自定义 XML 中的文本节点、属性、CDATA、注释。
  - 图片内容不做 OCR、不修改、不脱敏；预览时提示风险，脱敏导出前必须确认后继续，图片文件原样保留。
  - 嵌入对象、宏、修订记录、隐藏文本等无法可靠确认内容会阻断。
- 粘贴文本：
  - 预览和执行阶段按文本内容 hash 生成 `docId`。
  - 执行前若文本变化，需要重新预览。
  - 导出 `.txt` 和可选加密映射文件。
- 对无法可靠处理的对象要阻断或提示“存在未确认内容”，不能静默通过。

### 6. Electron 安全清单

- 敏感逻辑放在 main process、worker 或独立子进程。
- renderer 不直接接触密钥、映射明文、原始文件全文。
- 开启 `contextIsolation`、`sandbox`，关闭 renderer 的 Node 权限。
- IPC 只暴露最小 API：导入、脱敏、预览、导出、解锁映射、还原和实体集管理。
- IPC 参数必须做 schema 校验。
- 禁止加载不可信远程页面。
- 日志、崩溃报告、临时文件不得写入原文敏感信息。

### 7. 用户流程

1. 点击上传或拖拽 DOCX 文件，或粘贴文本。
2. 选择模式：不可逆脱敏 / 可逆实体脱敏。
3. 预览识别出的实体，允许用户确认、删除、补充。
4. 如需固定业务词库，在“实体集”页面维护并启用常见实体。
5. 执行脱敏。
6. 可逆模式输出脱敏文件和加密映射文件。
7. 还原时输入脱敏文本或文件、加密映射文件、口令或密钥文件。

### 8. 测试验收

- 验证导出的 DOCX / TXT 不能复制出原始敏感信息。
- 验证 Word 批注、修订、元数据无泄露。
- 验证错误口令无法解密映射。
- 验证 AI 删除实体后不会错误补回。
- 验证带稳定标签的 AI 摘要可以实体级还原。
- 验证安装包、asar、bundle 中不存在固定密钥。

## 后续开发建议

后续实现应以“设计清单 V1”为约束，先补齐安全边界、实体映射、加密映射文件和文档处理能力，再扩展任务记录、规则配置和批处理。

### 实现方向

- 新增独立文档处理层，负责文件读取、格式识别、文本抽取、敏感实体识别、文档写回和元数据清理。
- 新增实体映射层，负责同文档稳定替换、稳定 ID 生成、上下文定位和可逆映射维护。
- 新增加密层，负责随机 `DEK` 生成、映射表加密、口令或密钥文件派生密钥、加密包读写。
- 新增任务层，负责任务状态流转、错误收集和输出目录管理。
- 新增还原层，按实体映射和稳定标签执行实体级还原，不补回已被 AI 删除的实体。

### IPC 设计

后续 IPC 仅暴露最小必要能力：

- `document:import`：导入 DOCX、映射文件或密钥文件。
- `document:import-dropped`：导入拖拽得到的单个 DOCX 文件，仅支持脱敏和还原用途。
- `sanitize:preview`：按单个 `source` 预览识别出的实体。
- `sanitize:run`：按单个 `source` 执行脱敏。
- `output:export`：导出脱敏文件和加密映射文件。
- `mapping:unlock`：使用口令或密钥文件解锁映射。
- `restore:run`：按单个 `source` 执行实体级还原。
- `entity-sets:list`：读取本地实体集。
- `entity-sets:save`：保存实体集。
- `entity-sets:delete`：删除实体集。
- `entity-sets:import`：导入 JSON/CSV 实体集。
- `entity-sets:export`：导出 JSON/CSV 实体集。
- `task:get-list`：获取任务记录。

脱敏和还原的输入源使用统一结构：

```js
{ kind: "word", path: "D:/example.docx", docId: "optional-preview-doc-id" }
{ kind: "text", text: "粘贴文本内容", docId: "optional-preview-doc-id" }
```

其中 `docId` 用于脱敏执行前校验输入是否与预览一致；还原流程不需要传入 `docId`。

DOCX 含图片时，脱敏执行需额外传入确认字段：

```js
{ acknowledgements: { imageContentUnmodified: true } }
```

未确认时主进程返回 `DOCX_IMAGE_ACK_REQUIRED`，且不写出脱敏文件。

IPC 返回值建议统一结构：

```js
{
  ok: true,
  data: {},
  error: null
}
```

失败时：

```js
{
  ok: false,
  data: null,
  error: {
    code: "ERROR_CODE",
    message: "错误说明"
  }
}
```

### 状态管理

任务状态建议从简单枚举开始：

- `pending`：待处理
- `running`：处理中
- `success`：处理成功
- `failed`：处理失败

渲染层展示文案可映射为“待处理”、“处理中”、“已完成”、“失败”。

### 安全和隐私

本项目处理的文档可能包含敏感信息，后续开发应遵守以下约束：

- 默认只在本地处理文件，不上传原始文档。
- 映射表和处理日志应避免明文暴露敏感内容。
- 导出文件应写入用户明确选择的目录。
- 错误日志中不要记录完整敏感字段。
- 渲染层不直接访问文件系统，文件能力通过主进程受控暴露。

## 开发约定

- 保持主进程、preload、渲染层职责分离。
- 新增本地能力时先设计 IPC 接口，再实现调用链。
- UI 文案保持中文一致性。
- 文件编码统一使用 UTF-8。
- 文档更新与版本记录同步维护。
